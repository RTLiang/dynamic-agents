# Dashboard

## User behavior

The native table shows coding Hook sessions. Default order is Working, Completed, Idle, Unknown. Permission requests and user questions remain Working until the turn ends. A row opens its host App, leaving host window/tab/conversation selection unchanged.

## Executable journey

Run control hooks in a fresh isolated run. Require Build example before Memory project example before Review example. The normal Codex completion is retained, internal/background titles are absent. The helper selects the running row and presses Open App, checks the exact owned foreground host PID, and compares the host's retained second window and two-window count. AX evidence is hooks-dashboard.json; activation evidence is app-only-activation.json.

## Additional cases

For search/filter edits, enter a synthetic project into the real search field and inspect only matching rows, then clear it and exercise status filtering. For sorting edits inspect the actual table order. Pure model assertions do not prove those UI controls.
